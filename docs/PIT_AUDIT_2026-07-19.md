# PIT / leakage audit — findings & fix plan (2026-07-19)

> This is the one-off investigation. The durable rules it produced live in
> **`docs/PIT_RULES.md`** — read that one before writing new code; read this one for the
> evidence behind it.

Full audit of the longterm_agent stack for lookahead leakage (code) and result-distorting
methodology gaps (process). The core pipeline is PIT-sound: news corpus (`published <=
as_of`), decision-side prices (`tools/pit.daily_bar_cutoff`), fill/exit conventions
(`open_t1`/`open_d0`), the analog library window-completion rule, and the LLM cache are
clean. The findings below are the exceptions. Almost all live in the **deep-analysis
advisory path** — which was ON in ledger #9 (`wf_30x_v0.2_deep`, ACCEPTED), #11
(deep v2), and the just-launched `monday_t1` — plus one stale grader and a systematic
date-granularity gap that becomes a *post-entry* leak under `open_d0`.

Scope decision (owner, 2026-07-19): items in **Parked / development** (incl. the LLM
knowledge-cutoff gate and transaction costs) are explicitly deferred; everything in
**Fix now** is implementable today with no new data sources and no schema migrations.

## Status: F1–F10 IMPLEMENTED (2026-07-19), `PIPELINE_VERSION` 0.8.0 → 0.9.0

Detection labels are untouched (`DETECTION_VERSION` stands — the shift flag comes from map
sentiments and deterministic metrics), but tool outputs and the fundamentals /
characterization prompt inputs change, so runs across this bump are **not like-for-like** and
need a fresh `backtest_id`.

Three things the implementation turned up that the audit had not measured:

1. **The knowledge-date leak was large, not marginal.** On the live graph, gating events on
   "was any sourcing article published by as_of" removes **half** of what a 30-day NVDA
   window returned at `as_of=2026-05-01` (8 events → 4). Half the events a deep thread could
   previously read were only reported later.
2. **`Story.article_count` was not merely future-valued — it is broken as a count.** Story
   merges add 1 to the survivor instead of absorbing the merged story's count, so it drifts
   far below reality: a story whose stored `article_count` is 2 has 921 in-date sourcing
   articles. Both readers now count in-date articles, which is a well-defined PIT quantity
   but a **different, much larger unit** — so the novelty saturation constant
   (`STORY_SATURATION_ARTICLES`, still the old round 100) is now mis-scaled and owes a
   calibration pass. Scores before/after this change are not comparable.
3. **Latent bug found while testing F1**: the raw-Cypher size cap sliced the serialized JSON
   mid-token, so a large result set reached the model unparseable — and it truncated away the
   `pit_note` precisely in the ungated case that produces the most rows (i.e. the feedback
   would have been lost exactly when it mattered). Output now trims whole rows and puts the
   note first.

Verification: `test_pit_cutoffs.py` (9, pure), `test_deep_tools_canary.py` (5, integration),
`test_leakage_canary.py` (9, now parametrized over midnight + 06:30 cohorts),
`test_phase10.py` maturity cases, and a block-bootstrap check showing the cohort CI ~5×
wider than the per-trade CI on correlated cohorts. Suite after the re-check sweep below:
**253 passed** (232 `longterm_agent` + 21 `news_agent` — graph tools are shared, so the
knowledge-date gate is a correctness fix for the intraday agent too and its tests still
pass).

## Fix now

Ordering note: F1–F5 change deep-tool outputs (and F5b a detection-characterization
prompt input), so deep-enabled runs stop being like-for-like with pre-fix sweeps —
bump `PIPELINE_VERSION`, and treat any re-run as a new `backtest_id`. LLM-cache keys
change only for the affected calls; everything else replays.

### F1. Enforce PIT in `run_graph_query` in code, not in the docstring  ⚠ top priority
- **Problem** — `tools/analysis_tools.py:95`: the raw-Cypher tool enforces read-only but
  the `WHERE e.date <= datetime($as_of)` gate is only *requested* in the prompt. A query
  without the gate reads future events, including `AFFECTS` edges with realized
  `move_1d/move_4h`.
- **Fix** (two layers):
  1. Post-filter returned rows: walk each record's values; drop any row containing a
     Neo4j date/datetime > `as_of` (generic scan, `default=str` already stringifies —
     filter before serialization).
  2. Strip `move_15m/move_40m/move_4h/move_1d` keys from raw-Cypher results entirely.
     The curated tools expose them with proper maturity masking; the raw tool doesn't
     need them. Document both rules in the docstring.
- **Acceptance**: a test query with no date gate returns zero rows dated > as_of; a query
  returning `r.move_1d` comes back without that key.  **Size**: S.

### F2. Maturity-mask the intraday bridge
- **Problem** — `tools/intraday_tool.py:63` `_realized_moves` returns `move_1d` unmasked
  and the window (`:83`) ends exactly at `as_of`: events published < 1 trading day before
  as_of carry a realized move that extends *past* as_of. Contrast with the correct
  masking in `news_agent/tools/graph_tools.py:45`.
- **Fix**: only attach a move (and count it toward `hit`/`hit_rate`) for rows with
  `news_published <= as_of - 2 calendar days` (covers the weekend; no intraday
  bar-calendar join needed). Unmasked rows keep `realized_move_1d_pct: null`.
  Live impact ≈ none (a Friday event is mature by the Sunday/Monday batch).
- **Acceptance**: unit test on `format_reactions` + a fake row published as_of−1d →
  move is null, excluded from hit_rate.  **Size**: S.

### F3. Knowledge-date (not event-date) filtering in the curated graph tools
- **Problem** — all curated tools gate on `e.date <= $pub`, but `e.date` is the
  *real-world* event date. An event extracted from an article published AFTER as_of but
  dated in the past passes the filter ("the probe started in May" — revealed in July).
  Only `search_events` also checks `SOURCED_FROM.published_at` (`graph_tools.py:121`).
- **Fix**: extend the `search_events` precedent to the other 11 tools: require
  `EXISTS { (e)-[sf:SOURCED_FROM]->(:Article) WHERE sf.published_at IS NULL OR
  sf.published_at <= datetime($pub) }`. Keep the NULL-passes convention for parity with
  `search_events` (older ingests). Semantics are correct for the intraday agent too
  (its `pub` = article publish time), so the shared change is safe.
- **Acceptance**: graph fixture — event dated < as_of, sole source article published >
  as_of → not returned.  **Size**: M (12 queries, mechanical).

### F4. As-of story size instead of `s.article_count`
- **Problem** — `get_story_momentum` (`graph_tools.py:190`) and `get_novelty_score`
  (`graph_tools.py:315`, 40% of the score) read `s.article_count` — the story's
  *current/final* size. A backtest sees how big the narrative eventually became;
  "priced-in / saturation" readings are contaminated by the future.
- **Fix**: compute the as-of count in Cypher: distinct source articles of the story's
  in-date events (`(e)-[:PART_OF]->(s)`, `(e)-[sf:SOURCED_FROM]->(a)`,
  `sf.published_at <= $pub`), or fall back to the already-computed in-date
  `event_count`. Remove the raw `article_count` from tool outputs.
- **Acceptance**: fixture story with 3 pre-as_of and 5 post-as_of articles → tools
  report 3.  **Size**: M.

### F5. Same-day granularity: document dates must respect the session cutoff
- **Problem** — decision-side readers compare with `<= as_of.date()`:
  EDGAR `filed_date` (`tools/fundamentals_tool.py:43`), yfinance `fetch_date` (`:51`),
  FMP (`:380`), `filings` (`tools/filings_tool.py:37`), insider, `options_iv`,
  short-interest, `earnings_dates` (`tools/risk_tool.py:57`). For midnight cohorts this
  admits up to 24h of same-day documents (pre-entry under `open_t1`, but information a
  live agent at that timestamp could not have — concentrated exactly on filing days).
  Under **`open_d0`** (the running `monday_t1`: decide Mon 06:30, fill Mon 09:30) a
  Monday-16:30 filing is visible to the decision — a genuine **post-entry** leak.
  Sharpest case: the FMP retro fallback (`fundamentals_tool.py:383`, `fmp_is_pit=False`)
  filters records by report date `d <= as_of` — a report released the *evening* of
  as_of exposes `epsActual` to the 06:30 decision.
- **Fix** (no schema changes; all columns needed already exist):
  - *Filed/report-date fields* (EDGAR `filed_date`, FMP record `date`, `filings` +
    `insider_trades` `filed_date`): compare with `daily_bar_cutoff(as_of)` instead of
    `as_of.date()` — a document dated D becomes visible after D's session close, same
    rule prices already follow. Live post-close runs (hour ≥ 16) still see same-day
    filings; pre-open/midnight ones don't. Matches earnings-release timing (post-close).
  - *Fetch/snapshot fields* (yfinance & FMP `fetch_date` + `fundamentals.created_at`,
    `options_iv.snapshot_date` + `fetched_at`): knowability = OUR ingestion moment, so
    compare the timestamp: `fetch_date < as_of::date OR created_at <= as_of` (resp.
    `fetched_at`). Keeps the Sunday-05:00 weekly fetch visible to the Sunday-06:00 live
    batch (no live staleness regression) while excluding same-day-but-later snapshots
    in replays. **Pre-check**: confirm `created_at`/`fetched_at` are stored in ET (DB
    convention) before comparing; if UTC, convert in SQL.
- **F5b (same class)** — `_new_stories` (`tools/background_metrics.py:118`) orders
  candidate stories by current `article_count`; switch to the F4 as-of count. Note:
  this changes a characterization-prompt input (catalysts / `causal_event_types`), not
  the deterministic `shift_flag` — still bump `PIPELINE_VERSION`.
- **Acceptance**: canary at `as_of = D 06:30` sees nothing dated D from any reader
  (F8); live Sunday batch preflight still reports fundamentals fresh.  **Size**: M.

### F6. `full_signal_backtest.py` grades with the retired convention
- **Problem** — `full_signal_backtest.py:100` uses legacy `_ret` (entry = last close ≤
  as_of) — exactly the convention the 2026-07-19 `open_t1` regrade removed everywhere
  else (entry price printed before news the decision had read + the untradable gap
  credited to the trade). `grade_shifts._ret`'s own docstring says "do not grade with
  this".
- **Fix**: swap to `exit_rules.t1_return` for stock and SPY (mirror `backtest.grade`),
  or retire the script in favor of `backtest.py` if it no longer earns its keep.
- **Acceptance**: reuses the `open_t1` unit tests; a smoke run prints
  `fill_convention=open_t1`.  **Size**: S.

### F7. Analog window-completion tail under `open_t1`
- **Problem** — `tools/shift_library_tool.py:132` requires `as_of_analog + 28d ≤ as_of`,
  but graded outcomes are now anchored at the *entry bar* (as_of + 1..tolerance days),
  so an analog's outcome window can extend a few days past the cutoff.
- **Fix**: shift_library rows now carry `entry_date` (added by `grade_shifts`); filter
  `entry_date + 28d <= as_of` when present, fall back to the old rule otherwise.
- **Acceptance**: unit test with a boundary row (entry 3 days after as_of_analog).
  **Size**: S.

### F8. Second-generation leakage canaries
- **Problem** — the canaries (`tests/test_leakage_canary.py`) run at midnight as_of and
  assert `filed <= AS_OF.date()` — they *encode* the F5 granularity bug rather than
  catch it, and no canary covers the deep-analysis tools (where every real hole was).
- **Fix**:
  1. Parametrize the canaries over `as_of ∈ {D 00:00, D 06:30}` and assert **nothing
     dated D** is visible from any reader (post-F5 semantics).
  2. New `test_deep_tools_canary.py`: build `build_deep_analysis_tools` at a fixed
    as_of, invoke every tool with benign args, recursively scan the JSON output for
    ISO dates > as_of (generic scanner; skips cleanly when DB/graph are absent).
  3. Canary for `run_graph_query`: issue a deliberately ungated Cypher query; assert
     zero post-as_of rows and no `move_*` keys (F1's contract).
- **Size**: M.

### F9. Silent survivorship of halted/delisted paths → visible pending category
- **Problem** — `entry_bar` (7-day tolerance) and `_has_data_through` make grading
  *silently skip* rows whose price series never catches up. A halt/delisting mid-horizon
  — the worst possible outcome — simply vanishes from the book instead of being its
  worst row. Rare on mega-caps, but the asymmetry sits exactly in the tail.
- **Fix**: graders and `backtest.report()` count and print rows pending > N days
  (e.g. 14) past expected maturity as `STALE-UNGRADED (possible halt/delisting)`, per
  backtest_id/horizon, so the omission is visible instead of silent. No grading change.
- **Size**: S.

### F10. Cohort-block bootstrap alongside per-trade CIs
- **Problem** — weekly cohorts with 4w horizons overlap and share regime; per-trade
  bootstrap treats them as iid → CIs too narrow (the report's Sharpe is per-cohort, the
  CIs are not).
- **Fix**: `backtest_metrics.bootstrap_ci` gains a block mode — resample **cohorts**
  (as_of dates) with replacement, then pool their trades; report both CIs side by side.
- **Size**: M.

## Re-check 2026-07-19 (post-implementation sweep)

Verification pass over the fixes themselves, plus a hunt for anything the first audit
missed. Method: an unpruned scan that reports every future-dated field of every deep tool
(so the canary's own "legitimately forward" allowlist is audited, not trusted), a
column-type check on the timestamp clocks, and a grep sweep for surviving raw-date
comparisons on decision paths.

**Found and fixed — a regression I introduced.** `mature_move_ids` (F2) compared
`agent_results.news_published`, which is `timestamp WITH time zone`, against a naive ET
`as_of` → `TypeError`, so `get_intraday_reactions` raised on every call. Not a leak, but a
tool silently down is a tool whose PIT behaviour is unverified. Both sides now normalise
through `pit.as_moment`. **The canary had excused it** ("a tool that cannot run cannot
leak") — that clause is removed: an escaping exception now fails the test, since these
tools are written to degrade to `{"available": False}` rather than raise.

**Found and fixed — two same-day leaks the first audit had filed as "reporting-only".**
Both were real and neither was as harmless as recorded:
- `macro_series` was read with `date <= as_of.date()`, so a 06:30 pre-open decision saw
  VIX/oil/HY closes printed at 16:00 THAT DAY. Now on `daily_bar_cutoff`, and the process
  cache is keyed by cutoff rather than date (two runs either side of the close must not
  share an entry). Verified: 2026-07-17 06:30 now reads 07-16 macro, 16:30 reads 07-17.
- `backtest._regime()` measured SPY's trailing window ending at the as_of day's own close,
  attributing outcomes to a regime the decision could not observe.

**Confirmed clean** (checked, no action): `vector_similarity_search` filters
`published < timestamp − 1h`; `news.published` is naive so the corpus canary's comparison
is genuine; the v2/v3 daily sentiment series inherits the corpus bound; all 14 deep tools
scan clean with NO allowlist applied.

### Live sector lookup — FIXED (owner decision: the long-term agent is the primary consumer)

`analyze_sector_tool` called live `yf.Ticker().info` for sector/industry inside replayed
cohorts — reading today's classification, and making a backtest depend on a network
round-trip (a B0 reproducibility hole as much as a PIT one). Competitor PRICES were never
affected: `get_price_at_time` is genuinely point-in-time (verified — AMD resolves to 354.35
at as_of 2026-05-01 vs 500.93 at 2026-07-17).

Usage evidence made the first "just drop the tool" recommendation wrong: the tool is called
in **12/12** stored deep-enrichment runs — one of the five always-used tools. So the call
was repointed, not removed: `resolve_sector_industry()` resolves offline via the curated
`sector_map` → the as-of stored `info` snapshot → `'Unknown'`.

Measured cost of dropping the network path, which is why it was safe:
- **long-term agent: zero.** `sector_map` covers 119 of its 120 tickers, and the one gap
  (`SQ`) returns `None` from yfinance anyway. Tool output for NVDA is byte-identical.
- **ETFs: zero.** USO/SPY/TLT have no sector in yfinance either — and they are the bulk of
  the intraday agent's 135 uncovered tickers (68% of its signal rows).
- **intraday agent: loses sector labels for off-universe STOCKS** (BABA, DAL). Accepted per
  owner decision; `get_industry_competitors` already degrades to index proxies. Note this
  matters beyond live trading because `run_agent_batch.py` drives that agent with backdated
  timestamps, so the live call was a leak there too.

### Residual leakage — known, NOT fixed

1. **`_yf_hist_future` 45-day reporting-lag buffer** (`fundamentals_tool.py:417`). A
   company reporting more than 45 days after quarter-end leaks a surprise announced after
   `as_of`. Bounded and rare; a true fix needs report dates, not quarter-end labels.
2. **FMP retro path** (`fmp_is_pit=False`): realized-surprise history is read from a
   snapshot fetched AFTER `as_of`, resting on FMP's claim that per-report estimates are
   frozen at report time. Unverifiable from our side; already flagged advisory-only, and
   `next_report` is dropped on that path.

Both only affect the consensus feature, which is `false` by default.

## Parked / development (explicitly deferred 2026-07-19)

- **D1. LLM knowledge-cutoff gate** (was audit rec #5). Current models (Gemini 3 /
  3.1-flash-lite) have pre-2026 training cutoffs, so Apr–Jun-2026 cohorts can't be
  "remembered" — but nothing enforces this. **Blocking precondition for Track D**
  (DATA_EXPANSION_PLAN news depth to 2016+): a 2020–2024 backtest sits inside every
  modern model's memory (the model knows what happened to COVID names, 2022, NVDA…).
  Plan: stamp each model's knowledge cutoff in `provenance()`; preflight refuses
  cohorts `as_of < cutoff + margin` unless explicitly overridden. Also applies to the
  queued `wf_30x_strong` (newer-cutoff candidate model).
- **D2. Transaction costs / borrow in reports** (was audit rec #6). Acceptance §7.4
  ("net of turnover") already requires it before any *verdict* claim; at current
  mean-excess magnitudes (+0.5–0.9pp per 4w) costs can consume the entire effect.
  Plan: flat spread assumption per side + borrow for SHORTs, printed as a third book.
- **D3. EDGAR acceptance-datetime** — the true intra-day PIT key for filings (SEC
  publishes it); replaces the F5 session-cutoff approximation. Needs a fetcher change +
  backfill.
- **D4. `valuation_pit` split correctness** — retro split-adjusted price × implied
  shares from a pre-split filing breaks P/E by the split factor (also a live bug;
  contradicts the "immune to share splits" comment). Interim guard (cheap, can ship
  with F-block): log/flag when EDGAR-implied shares disagree > 30% with the yfinance
  snapshot's `sharesOutstanding` where both exist. Real fix: DEI
  `EntityCommonStockSharesOutstanding` from the filing cover page.
- **D5. Universe-as-of** — the curated TOP_50 list is today's knowledge; harmless on a
  3-month window, classic survivorship once Track D enables multi-year backtests.
  Plan: freeze universe membership per cohort date (index-membership snapshots).

## Explicitly fine (audited, no action)

- Live weekend/pre-open runs cannot leak (future data doesn't exist at run time); every
  finding above concerns replay/backtest honesty — i.e. backtest-vs-live optimism.
- Replay-vs-live data drift (graph gaining AFFECTS edges over time, richer analog
  library than live had, snapshot sources existing only from 2026-06/07) is a known,
  printed asymmetry (`compare_detections.py`), not lookahead; keep printing it.
- `_regime` / regime-context stamps read the as_of day's own close/macro print for
  midnight cohorts — reporting-only splits, nothing gates on them; fold into F5 only
  if free while touching those readers.
- Dividends absent from raw-close returns: symmetric with the SPY leg; noted, accepted.
