# Significance Classifier — План эксперимента

Лёгкий гибридный классификатор (регулярки/лексика + эмбеддинги), который по
заголовку+саммари новости на момент публикации предсказывает, **значима** ли
новость = двинет ли цену её тикера в коротком окне. Используется как **дешёвый
пре-фильтр** (бинарный + калиброванный score 0–1) перед дорогим LLM-агентом,
чтобы резать шум и экономить вызовы, не теряя значимые новости.

Решения зафиксированы: **метка = движение цены**, **роль = пре-фильтр (бинарный + score)**.

---

## 1. Гипотезы

- **H1 (основная):** гибрид (regex ⊕ emb) > regex-only и > emb-only по PR-AUC и
  recall@budget на временно́м тесте.
- **H2:** калиброванный score позволяет на фикс. бюджете LLM (X% новостей)
  удерживать ≥90–95% значимых новостей.
- **H3 (бизнес):** гейт перед агентом сохраняет P&L при заметно меньшем числе
  LLM-вызовов (проверка через `profit_compute`).

Эксперимент «успешен», если H1 подтверждается с заметным отрывом и H3 не
ухудшает P&L.

---

## 2. Определения

**Единица анализа:** статья (нужно ли отдавать её агенту). Метка — по максимуму
движения среди замапленных тикеров (multi-ticker статья значима, если двинулся
хотя бы один). Вторичный трек: гранулярность (статья, тикер).

**Метка (движение цены):**
- Для статьи в `t0` и каждого тикера: forward-return за окно `W` — вход по первой
  доступной цене `≥ t0`, выход в `t0 + W`. Данные — 1-мин через `get_price_range`.
- `move = max_тикеры |r_excess|`, где `r_excess = r_тикер − r_benchmark` за то же
  окно (вычитаем рынок, чтобы не путать общерыночное движение с реакцией на новость).
  v1 — можно сырой `|r|`; v2 — excess к SPY/сектору.
- **Метка = 1**, если `move ≥ τ`. Порог `τ` — **волатильностно-нормированный**:
  `|r| ≥ k·σ_тикер(W)`, `k≈2–3` (устойчивее между волатильными и спокойными
  именами), плюс абсолютный % как sanity-check.
- Окна: `W ∈ {15, 30, 60} мин` — основное выбираем по балансу классов и сигналу.

**Защита от утечек (критично для финансов):**
- Признаки — только доступные на `t0` (заголовок, саммари, тикеры, время суток,
  источник). Никаких пост-новостных полей.
- Вход строго `≥ t0` (без look-ahead). Halts / пропуски минут / неликвид — drop
  или пометка `unknown`.
- **Сплит временно́й** (старое → train, новое → test), не случайный; группировка
  по статье, чтобы multi-ticker строки не попадали в оба сплита.
- Утечка цены до новости (`pre_news_movement_tool`) — для метки значимости новость
  всё равно значима; добавляем флаг и анализируем отдельно.

> на этапе загрузки и уже покрывает 15k статей и 2146 тикеров.

**Размечаемый датасет (пересечение граф × ценовой универсум × окно × эмбеддинг):**
- **10 539 размечаемых статей** (граф-маппинг на ≥1 из 121 priced-тикеров, в окне цен, с эмбеддингом);

**Нюанс «фокусные vs макро»:** гистограмма #priced-тикеров на статью имеет длинный
хвост — много макро/market-wide статей мапятся на 20–48 тикеров (там «какой тикер
двинулся» размыт и метка «хоть один двинулся» почти всегда =1). Поэтому:
- **v1 — фокусные статьи (≤3–5 priced-тикеров): ~3 300–4 500 статей** — чистая
  однонейм-новость, значимость определена корректно;
- макро-статьи (большой fan-out) — отдельный трек/анализ, не мешаем в v1.

**Пайплайн сборки (Фаза 0, без LLM):**
1. PG: список priced-тикеров (из `information_schema`, префикс `historical_data_`),
   множество news_id в окне цен с эмбеддингом.
2. Neo4j: `news_id → [tickers]` одним Cypher-запросом (см. выше).
3. Пересечение в pandas → отбор фокусных статей.
4. Метки: для каждой пары (news_id, ticker) считаем движение цены через
   `get_price_range` (вход ≥ t0). → parquet: `news_id, t0, ticker, source/news_type,
   move, move_z, label, n_tickers, split`.

Ожидается дисбаланс (значимых меньшинство) → PR-метрики, веса классов, тюнинг
порога; **без наивного оверсэмплинга**.

### Результаты Фазы 0 (прогон `significance/phase0_labeling.py`)

Датасет собран **без единого LLM-вызова**. **Решение: новости вне торговых часов
отбрасываются сразу** (`GAP_MAX_MIN=3` — рынок должен торговать в момент t0; вход
по next-open не оцениваем, т.к. это конфликтует с волатильностью открытия). Окно
W валидно только если закрывается внутри той же сессии (без overnight).

`significance/data/labels.parquet`:

| | пары | новости | тикеры | base rate (z≥2σ@30) |
|---|---|---|---|---|
| Все intraday | 36 756 | 3 233 | 112 | 5.7% |
| Фокусные (≤5) | 3 526 | 1 349 | — | 5.6% (article-level: 10.2%) |

~99% с эмбеддингами. Проверка tz: t0 строго 09–15h ET, gap median 0.4 мин,
overnight 0% — выравнивание корректное. **Gate пройден** (сигнал есть), но:

- **мелкие движения**: `abs_ret_30` p50=0.22%, p95=0.93%, p99=1.6%;
- **дисбаланс ~5.7%** → PR-метрики, веса классов, тюнинг порога обязательны;
- pair-level 36k строк делят текст лишь **3 233 статей** → для pair-level нужны
  тикер-специфичные фичи; для чистого «гейта на статью» естественнее
  **article-level** (фокусные, base rate 10.2%, n=1 349).

Определения метки @W30 (фокус): abs≥0.5%=18.4%, ≥1%=4.3%, ≥2%=0.5%; z≥2σ=5.6%
(стабильно по W — нормирована на σ).

**Сплит:** временной, train ≤ 2026-05-14 / val ≤ 2026-05-26 / test > 2026-05-26.
Тест тонкий (~10 дней, ценовое окно Feb–Jun 2026) → нужен walk-forward.

### Результаты Фазы 1 (featurization — вариант A, pair-level)

Матрица `significance/data/features_tabular.parquet`: **34 597 пар × 64 табличных
фичи + эмбеддинги 1536-d** (`embeddings.npz`, на новость). Pos rate 5.7%.
Скрипты: `regex_featurizer.py`, `graph_features.py`, `load_text_embeddings.py`,
`build_dataset.py` (+ тесты `tests/`). Всё собрано без LLM.

**Семейства фич:** regex/лексика (30), graph_pair (6: `AFFECTS` conf/sentiment,
fan-out), graph_article (17: `Event.type`-таксономия, диффузность), ticker (3:
ликвидность/уровень/дисперсия цены), structural (8: время суток, dow, source,
диффузность), embeddings (1536).

**Решения, скорректированные данными:**
- `canonical_entity` в граф не записан, `AFFECTS.confidence` не дискриминирует
  (медиана 2 тикера делят максимум) → **«primary-тикер» из графа недоступен**,
  идея отозвана.
- Новости в основном диффузные (компаний/новость: медиана 14, среднее 46);
  истинно single-name (≤3 компаний) ~20%. → **диффузность стала фичей**, не
  фильтром. **Главная метрика — pair-level PR-AUC** (метка на пару).

**Leakage-аудит:** сплит без пересечений (0 новостей в >1 split), train<test по
времени, target-фичи не протекли, 0 NaN. **Два «мягких» каведа для финала**
(не ловятся колоночным аудитом, не для v1-PoC):
1. граф-фичи отражают событие *в текущем (смерженном) виде* — поздние статьи могли
   дорастить набор компаний/сентимент → лёгкая утечка будущего;
2. `σ` метки и тикер-статы (`tk_disp/tk_log_vol`) считаны по всей истории →
   лёгкий look-ahead волатильностного режима.
Фикс для финала — считать и то и другое **as-of-t0** (скользящее окно до публикации).

### Результаты Фазы 2 (абляция) — ⚠️ негативный, но важный результат

Test (base rate 7.9%), PR-AUC: regex 0.082 · emb 0.108 · **meta 0.286** ·
**hybrid 0.307** · late-stack 0.281. На первый взгляд гибрид > одиночных. **Но
групповая permutation-importance вскрыла, что это иллюзия:**

| модальность | ΔPR-AUC при разрушении |
|---|---|
| regex | **+0.001** (≈ничего) |
| embeddings | **+0.010** (≈ничего) |
| meta | **+0.224** (всё) |

А внутри meta доминирует **одна фича — `tod_mins_since_open` (+0.166)**. Причина —
**time-of-day confound**: base rate |move|≥2σ@30 = **23.5% на открытии → 1.2% в
конце дня** (×20, corr −0.23). Плоская (средне-дневная) σ не учитывает
внутридневную кривую волатильности (открытие ≫ midday), поэтому метка «значимо»
почти эквивалентна «вышло у открытия». **Модель учит часы, а не новость.**

**Вывод:** (1) текст (regex+embeddings) даёт **нулевой** сигнал на этом таргете;
(2) видимая «производительность» — артефакт времени суток, а не значимость.
Исходная гипотеза «regex+эмбеддинги» на intraday-таргете **не подтверждается**, и
сама метка пока слишком confounded, чтобы честно её проверить.

**Что нужно:** time-of-day-условная σ (значимо = |move|≥2σ **для этого времени
суток**) → перегенерить метки → перезапустить абляцию. Честный кавеат: даже после
фикса текст может остаться слабым intraday — крупные контентные движения (earnings)
в основном **after-hours**, которые мы исключили. То есть для проверки идеи
«regex+эмбеддинги» по-настоящему, вероятно, нужен after-hours-режим.

## 4. Признаки

**A. Regex / лексика (дёшево, интерпретируемо):**
- Флаги типов событий по курируемым лексиконам: earnings/guidance, M&A,
  FDA/trial, upgrade/downgrade, lawsuit/SEC/probe, bankruptcy, buyback/dividend,
  layoffs, contract/partnership, CEO/CFO change, short-seller report.
- Числовые сигналы: наличие %, $-сумм, «beats/misses», слова-маркеры
  («surges/plunges/soars/tumbles/halts»).
- Структурные: длина заголовка, доля CAPS, число тикеров, источник, время суток
  (pre-market/open/intraday/after-hours — сильно влияет на движение), день недели,
  earnings-season.
- Реализация: `RegexFeaturizer` → вектор + сырые булевы флаги (для правил и
  интерпретации).

**B. Эмбеддинги:**
- 1536-d эмбеддинг title+summary (переиспользуем).
- Опционально PCA до ~128–256 (меньше оверфита/быстрее) — сравнить с/без.
- Опционально «семантический kNN-приор»: средняя метка `k` ближайших исторических
  новостей через `vector_similarity_search` — **только по прошлым/train-новостям**
  (иначе утечка). Мостик между эмбеддингами и меткой, переиспользует pgvector.

**C. Фьюжн (собственно «гибрид»):**
- **M0 baselines:** regex-only; emb-only; тривиальный (base rate / чистая
  keyword-эвристика).
- **M1 early fusion:** `concat[regex ⊕ emb(или PCA)]` → LightGBM/XGBoost (+
  логрегрессия). Деревья хорошо едят смешанные dense+bool, дают важность фич.
- **M2 late fusion / stacking:** отдельные regex- и emb-модели, блендинг
  вероятностей логрег-мета-учеником (компоненты тюнятся/сервятся независимо).
- **M3 (позже):** маленький MLP над `[emb ⊕ regex]` — только если M1/M2 упрутся.
- **Калибровка** (isotonic/Platt) обязательна — мы порогуем score (reliability +
  Brier).

Старт простой: ядро — M1 и M2; regex-only и emb-only — абляции под H1.

## 5. Оценка

**Сплит:** временно́й, по статьям — train (≈70% старого), val (≈15%), test (≈15%
нового). Финальные числа — только на новом тесте. Робастность — walk-forward.

**Метрики (дисбаланс → ранжирование/PR):**
- **PR-AUC (average precision)** — основная.
- ROC-AUC — вторичная.
- **Recall@budget** — при фикс. доле новостей, уходящих агенту (бюджет LLM),
  какую долю значимых удержали. Кривая recall vs %-пропущено (стоимость).
- Precision@k / lift над base rate.
- Калибровка: Brier, reliability-диаграмма.

**Выбор порога:** на val под цель «удержать ≥90–95% значимых» (FN дороже FP:
пропущенная значимая новость хуже лишнего LLM-вызова — это в веса классов и в
порог). Репортим итоговое сокращение LLM-стоимости (% отфильтрованного).

**Абляция (прямой тест идеи):**

| Модель        | Regex | Emb | Фьюжн       |
|---------------|:-----:|:---:|-------------|
| regex-only    |   ✓   |     | —           |
| emb-only      |       |  ✓  | —           |
| hybrid early  |   ✓   |  ✓  | concat→GBM  |
| hybrid late   |   ✓   |  ✓  | stacking    |

Сравнение PR-AUC и recall@budget с bootstrap-CI по статьям теста.

**Downstream-валидация (главное доказательство):** встроить гейт в
`batch_analysis`/агент (агент только на прошедших гейт), затем
`profit_compute/trade_simulator` — сравнить gated vs ungated: (а) P&L,
(б) число/стоимость LLM-вызовов, (в) Sharpe/hit-rate. Победа: близкий/лучший P&L
при заметно меньшем числе вызовов.

## 7. Фазы и артефакты

- **Фаза 0 — Данные и метки.** Скрипт лейблинга (движение цены через
  `get_price_range`), маппинг статья→тикер, временно́й leakage-safe сплит. Артефакт:
  размеченный датасет + EDA (распределение движений, base rate, по времени
  суток/типу события). **Gate:** есть ли обучаемый сигнал (keyword-флаги уже дают
  lift над base rate)?
- **Фаза 1 — Признаки.** `RegexFeaturizer` (+лексикон) и загрузчик эмбеддингов
  (pgvector / `EmbeddingGenerator`), кэш матриц. Юнит-тесты фичеризеров + аудит
  утечек.
- **Фаза 2 — Бейзлайны и абляция.** regex-only, emb-only, hybrid (early+late),
  калибровка → таблица метрик + кривые PR/recall-cost + bootstrap-CI. Отвечает на
  основной вопрос (H1).
- **Фаза 3 — Рабочая точка и робастность.** Порог под целевой recall;
  walk-forward; error-analysis (какие значимые пропускаем / что зря пропускаем);
  интерпретация (топ regex-флагов + SHAP по GBM).
- **Фаза 4 — Downstream и интеграция.** Гейт за флагом в batch/agent; бэктест P&L
  и стоимости vs ungated через `profit_compute`. Go/no-go на продакшн.

## 8. Риски и подводные камни

- Временна́я утечка / look-ahead в метках (вход строго `≥ t0`; kNN-приор — только
  по прошлому).
- Шум меток: общерыночные движения как «реакция на новость» → excess /
  vol-нормированный return; пограничные случаи позже можно чистить LLM-ом.
- Неликвид/halts/пропуски минут/after-hours → правила фильтрации и пометки.
- Дисбаланс → PR-метрики, веса, тюнинг порога (не accuracy).
- Популяция валидности: только новости с замапленными tradable-тикерами —
  задокументировать.
- Дрейф эмбеддинг-модели → пин `gemini-embedding-001` / 1536-d, фикс. шаблон текста.
- Сдвиг распределения во времени → walk-forward, периодический ретрейн.
